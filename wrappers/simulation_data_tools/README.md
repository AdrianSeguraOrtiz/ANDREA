# simulation_data_tools

Wrapper and maintenance tooling for the packaged simulator catalog in `andrea/catalog_simulation_data_tools/`.

Use this area for:
- validating SimulatorSpecs
- validating simulator smoketest configs
- building simulator Docker images
- pushing/pulling simulator Docker images
- running simulator smoketests
- benchmarking simulator runtime cost profiles
- scaffolding new simulator integrations
- validating shared simulator input specs
- extracting local simulator paper PDFs
- keeping smoketest parameter overrides for small, fast runs

Runtime catalog assets consumed by `andrea generate-data` live in `andrea/catalog_simulation_data_tools/`.
Simulator build sources live in `wrappers/simulation_data_tools/simulators/`.
Smoketest parameter overrides live in `wrappers/simulation_data_tools/param_overrides/`.
Simulator cost benchmark profile configs live in `wrappers/simulation_data_tools/cost_profiles/`.

## Normalized Output Contract

Every simulator wrapper writes normalized outputs directly under `/work/out/`.
The public truth contract is a single context-aware edge table:

```text
expression.tsv
truth/
  networks.csv
  gene_universe.txt
extras/
provenance/
  raw/
simulator-output-manifest.json
progress.json
```

All public truth networks are exported through `truth/networks.csv`, with
columns `source,target,score,sign,evidence,context`. The `context` value
determines whether an edge belongs to global, group or column-specific truth.
Use `context=global` for dataset-level truth and `context=group:<id>` for
group-specific truth. Use `context=column:<id>` for column-specific truth, where
`<id>` should match an expression column. Column-specific truth is not an
infer-network extra input; it is public benchmark truth in this same table.
The manifests reference this table through `outputs.networks` and
`truth.networks`. Simulators may preserve native outputs under provenance, but
public consumers must not depend on those native files.

## Layout

```text
wrappers/simulation_data_tools/
  param_overrides/
    <simulator_id>.json  # optional, merged before per-config smoketest params
  cost_profiles/
    <simulator_id>.json  # benchmark matrix used to generate catalog cost.json
  simulators/
    <simulator_id>/
      Dockerfile
      run_simulator.py | run_simulator.R | run_simulator.sh
      repo/             # optional local clone of simulatorspec.implementation_url
      papers/           # optional local publication cache
  scripts/
    shared/
    scaffold_simulator.py
    prepare_simulator_papers.py
    validate_input_specs.py
    validate_simulatorspecs.py
    validate_smoketest_configs.py
    validate_simulator_costs.py
    benchmark_costs.py
    build_simulator_images.py
    sync_simulator_images.py
    run_smoketests.py
  SIMULATOR_INTEGRATION_PLAYBOOK.md
  tests/
    schemas/
      smoketest.config.schema.json
    smoketest_configs/
      <simulator_id>_*.json
```

```text
andrea/catalog_simulation_data_tools/
  schemas/
  input_specs/
    <input_id>.json    # reusable simulator-side input-file contract
  simulators/
    <simulator_id>/
      simulatorspec.json
      cost.json          # optional, generated by benchmark_costs.py
```

Simulator-side input files are split across two catalog layers:

- `input_specs/<input_id>.json` defines reusable file semantics, format,
  accepted extensions, examples and validation notes.
- `simulators/<simulator_id>/simulatorspec.json` declares simulator-specific
  `extra_inputs` usage: required, optional and conditional requirements.

Generated extras under benchmark packages are outputs of the simulator and are
not simulator-side inputs.

## Scripts

```bash
python wrappers/simulation_data_tools/scripts/validate_input_specs.py
python wrappers/simulation_data_tools/scripts/validate_simulatorspecs.py
python wrappers/simulation_data_tools/scripts/validate_smoketest_configs.py
python wrappers/simulation_data_tools/scripts/validate_simulator_costs.py
python wrappers/simulation_data_tools/scripts/build_simulator_images.py --list
python wrappers/simulation_data_tools/scripts/run_smoketests.py --list
```

`run_smoketests.py` builds the simulator image unless `--skip-build` is provided.
Smoketest params are resolved from `param_overrides/<simulator_id>.json` plus each config's `request.params`, with the config taking precedence.

## Generate-Data Planning And ETA

`andrea generate-data plan` resolves simulator params, conditional simulator
inputs, resource assignments and ETA estimates into `simulation-plan.json`.
Parallelism is planned as execution resources, not simulator params:

```bash
andrea generate-data plan \
  --scenario scenario-request.json \
  --simulator-runs simulator-runs.json \
  --out simulation-plan.json \
  --max-parallel-tasks 2 \
  --max-cores 8 \
  --max-ram-gb 32

andrea generate-data run \
  --plan simulation-plan.json \
  --output-dir benchmarks
```

The end-to-end form accepts the same planning limits:

```bash
andrea generate-data execute \
  --scenario scenario-request.json \
  --simulator-runs simulator-runs.json \
  --output-dir benchmarks \
  --max-parallel-tasks 2 \
  --max-cores 8 \
  --max-ram-gb 32
```

If `andrea/catalog_simulation_data_tools/simulators/<simulator_id>/cost.json`
exists, the planner uses it to choose `runtime_resources.threads`, per-task
RAM/ETA and execution waves. If no cost profile exists, the plan remains valid
and records a conservative fallback `eta_source` plus warnings in
`execution.warnings`.

## Adding A Simulator

1. Run `make scaffold-simulator SIMULATOR=<simulator_id>`.
2. Place upstream evidence under `wrappers/simulation_data_tools/simulators/<simulator_id>/repo/` and local papers under `papers/`.
3. Follow `wrappers/simulation_data_tools/SIMULATOR_INTEGRATION_PLAYBOOK.md`.
4. Model supported datasets with `data_axes`, `truth_requirements` and
   `capabilities`; do not reintroduce combined profile names.
5. Keep expensive smoketest defaults in `param_overrides/<simulator_id>.json`; keep scenario-specific deltas in `tests/smoketest_configs/`.
